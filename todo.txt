================================================================================
DOCTRINE (3 axes)
================================================================================

Axe 1 — zéro duplication JSX : dès qu'un pattern se répète (≥ 2-3×), extraire
  un sous-composant présentationnel pur (props in, JSX out, pas de state métier).
Axe 2 — logique métier uniquement dans pages/hooks. Composant avec useEffect
  conditionnel, tri, fetch, ou plusieurs sources de state → hook `use…`.
Axe 3 — CSS Modules co-localisés, `@reference` obligatoire, `composes` intra-
  fichier uniquement, `data-*` pour états/variantes, `shared.module.css` via
  import JS direct pour délégations pures transverses (≥ 3 composants).

================================================================================
RAPPELS TECHNIQUES
================================================================================

- Tailwind v4 (pas de tailwind.config.js) — `@reference` requis en première
  ligne de chaque .module.css
- Alias `@` → `src/`
- DimField : `{ field: string; dateGroup?: DateGrouping }`
- normalizeConfig() dans useReportPage.ts migre les anciens string[] → à
  conserver lors du split PR A
- Worker pivot : un seul actif à la fois, terminate avant de relancer
- composes cross-file CASSÉ avec @tailwindcss/vite (voir memory) —
  shared.module.css consommé via import JS direct uniquement
- Vérif double-hash post-build :
  grep -oE '_<class>_[a-zA-Z0-9_]+' dist/assets/index-*.{js,css} | sort -u
  → un seul hash par classe attendu
